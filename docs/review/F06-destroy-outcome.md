# F06: confirm a destroyed session after its committed reply is lost

The independent verifier found that a fresh explicit destroy retry still failed after the server deleted the live authorization row. The actual HTTP regression first commits destruction, holds its successful reply, cancels the caller, then retries against the same retained SID with a fresh proof. The baseline fails in Stream.destroySession with Session revocation rejected. The earlier cancellation test held the request before commit and did not cover this case.

Destroy now atomically retains the former public verification key in an additive store before deleting live authority. SessionProofVerifier may consult this key only for the DESTROY domain when live authority is absent and the SID is permanently revoked. Fresh, time-bounded signatures can confirm the terminal outcome. Existing consumed nonces, unsigned requests and different keys remain rejected. The key cannot authorize subscription, push or any other live mutation, and the SID cannot be recreated. No challenge or private material survives. One retained key per admitted permanently reserved SID shares the existing namespace bound; mutable read results are copied.

Custom SessionStore implementations retain fail-closed behavior unless they implement the additive revokedVerificationKey seam. Historical revocations with no recoverable public key cannot authenticate confirmation; no authority is invented for them. Frozen V1 definitions and wire bytes remain unchanged; the new store is an additive V4 declaration.

Three real HTTP destroy regressions, three server revocation cases (including SQLite reopen and independent actual PostgreSQL handles), the public proof boundary and both frozen-schema adoption tests pass: nine tests, zero failures or skips on the status-final immutable dependency manifest. The persistence test also proves consumed-nonce rejection after reopen, wrong-key and unsigned rejection, no live subscription authority, permanent reservation and detached key reads. Logs and actual failing test XML are in evidence/F06-destroy-outcome-{red,green}.log and evidence/F06-destroy-outcome-red.xml. Final combined and independent verification remain required.
