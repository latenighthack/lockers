# F03 — monotonic authority and V2 signing

The baseline replay regression removed a re-established lock with the original
unlock signature. It failed before the fix. Unlock now stores an unlocked
tombstone and advances the incarnation; establishment advances it again.
Descendants are explicitly revoked when their parent is unlocked, retaining
their monotonic tombstones. The scope-state RPC exposes optimistic versions.

V2 domains bind authority versions into grants, unlocks, writes and ratchets.
Write signatures bind notifications; ratchet signatures bind shared-key
metadata. The original V1 preimages remain unchanged. V1 proofs are accepted
only for the initial authority incarnation and cannot authorize metadata or a
later incarnation. Capabilities advertises V2 negotiation to new connectors.

Tests prove V2 delegation/unlock success, reject replay after target recreation,
reject modified notification metadata and preserve the original hierarchy and
write regressions. `:server:test --tests '*LockVerifierTest*' --tests
'*ReviewRegressionTest*'` passes (12 tests) with patched workspace dependencies.
Client V2 integration and atomic hierarchy mutation (F08) remain final gates.
