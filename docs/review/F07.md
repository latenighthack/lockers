# F07 — authoritative lock resolution

Reproduction: two room services share one database. One reads an open room, the
other establishes a room authority, then the first submits an unsigned write.
The baseline accepted it. `ReviewRegressionTest.newAuthorityIsEnforcedAfterAnotherReplicaReadAnOpenRoom`
now rejects it. The two security regressions in that class pass.

Removed the indefinite positive/negative `roomHasLocksCache` gate. Reads and
writes resolve effective authority from storage. F08 places mutation resolution
inside the same shared transaction as content and authority updates.
