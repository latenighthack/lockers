# F38 shared verification work admission

Red reproductions: valid-length forged session proofs consumed P-256 work without any finite request budget; invalid curve create requests could likewise flood decompression. Encoded proof requests were hashed before any admission. Separate service paths did not share an operator budget. All four public boundary regressions fail on the isolated baseline.

ServerCore now provides one shared per-node CpuAdmission for room writes, session handshakes and proof verification. Cheap identity, encoded-size, signature/key-length/prefix gates reject before admission. Admission charges estimated key/signature operations and one additional unit per64KiB of encoded input before digest, decompression, verification or database work. Writes allow up to12crypto operations per change, including ratchet/enclosure checks. Defaults are2000units/second with burst4000, supporting the50write/second validation workload; strict environment settings LOCKERS_CPU_UNITS_PER_SEC and LOCKERS_CPU_BURST tune it. Room/proof rejection is RESOURCE_EXHAUSTED; handshake rejection is Open.RESOURCE_EXHAUSTED for the SDK retry contract.

Validation: CpuAdmissionBoundaryTest checks forged valid-length proofs reject at capacity without mutation or staged replay rows, malformed cheap shapes do not consume handshake work, invalid-curve decompression is bounded, encoded request bytes exhaust weighted admission before hashing/storage, and the actual dependency graph shares capacity across a successful create/proof and subsequent write. The final suite also passes session key/error boundaries, public proof/replay checks, durable inbox1030ACK stress and complete response ceilings.
