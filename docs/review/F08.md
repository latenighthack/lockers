# F08 — commit-time room ownership fencing

Reproduction: restore the bare JDBC driver while retaining the captured claim
proof. The actual PostgreSQL stale-claim regression then commits after ownership
has moved. The fixed driver rejects it and leaves content and delivery intent
absent. A second regression expires the claim during the transaction and verifies
both source and intent roll back.

Room mutation admission captures ownership in the coroutine context. The storage
transaction checks that proof on the same connection before mutation and before
commit. PostgreSQL claim rows are locked and checked against database time;
released claims preserve monotonically increasing epochs. Each configured node
label receives a process incarnation UUID. Ring ownership uses a durable,
monotonic coordinator token whose row is locked during source commit. Unsupported
persistent ownership implementations fail closed. Local and in-memory ownership
follow the same transaction guard contract.

Four actual PostgreSQL regressions cover stale claims, expiration during commit,
stale ring tokens despite stale local liveness, and competing writes through two
database handles. These plus fourteen authority, receipt and ratchet regressions
pass with required PostgreSQL enabled. Logs: /tmp/lockers-F08-pg-red.log and
/tmp/lockers-F08-final-green.log. Final integration and platform gates remain.
