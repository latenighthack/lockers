# F37 — immutable source commit metadata and cold receipt observations

Reproduction: a response marked `agentIndeterminate` returned ordinary success even though derived execution could not be classified. The source-status regression failed before the fix (`/tmp/connector-F37-repro.log`).

Fix: pending, failed and indeterminate agent responses accept committed source/cache and ratchet keys before reporting a typed `LockerSourceCommittedException`. The exception exposes copied receipt id, room and complete per-locker version metadata; mutating returned arrays cannot corrupt recovery identity. A no-op adoption retains its receipt and private recovery key but still accepts the committed source cache before reporting adoption pending. Batch cache acceptance is atomic and requires complete committed metadata.

`writeOutcomes`/`awaitWriteOutcome` are cold and parent-owned. They emit immutable copies of precise response/result metadata, suppress unchanged observations, and finish at APPLIED/FAILED/INDETERMINATE or a configurable deadline (default five minutes). UNKNOWN/NOT_FOUND stay observable until the deadline; unavailable/unsupported states are typed terminal observations. Deadline/cancellation cancels a held RPC rather than leaving a detached polling job. INDETERMINATE requires trusted manual reconciliation; the SDK never blindly resubmits a write or reruns the agent. The server retention contract keeps completed metadata at least 31 days, beyond its 30-day automatic retry window, while pending/running/indeterminate metadata remains recoverable. Historical V1 identities are not fabricated.

Verification: indeterminate source acceptance, immutable metadata, cold/distinct terminal polling, missing receipt deadline, and held-RPC cancellation tests pass alongside ratchet/authority regressions (`/tmp/connector-F37-fix.log`). API prerequisite `2b1bee7` is already owned by the root integration; the local unsupported server fixture is not part of the fix commit.
