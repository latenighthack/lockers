# F11 legacy archive recovery follow-up

Two public SDK regressions fail at75b05c5 before the source fix. On startup against an upgraded authorityV2 server, a valid legacy archive has no recorded scope and epoch0, while the active room ancestor has the archived public key at epoch2. The synthetic locker scope has no lock and epoch0. Recovery previously queried that synthetic scope and deleted the archive as obsolete; the provider never received its still-active key. Recovery now uses effective GetLocker authority for archives without exact scope/positive epoch metadata. Only recorded exact V2 history can prove an archive obsolete; an effective mismatch retains the private archive. Authority discovery errors are checked before adoption.

A second regression calls updateLocker with a committed archive lacking its previous write-signature public key and a provider holding an unrelated key. Recovery previously invoked the adoption callback and overwrote the provider key before attempting a new source. It now reports RatchetAdoptionPendingException and retains the archive, leaving that provider unchanged. Known previous signing identity remains required to replace a non-null different provider key.
