# F38 immutable bounded snapshot pages

Red repro: a public GetAllLockers request specifying 64 items returned all 130 rows and ignored its paging contract (isolated baseline d97f7a7). Concurrent changes also meant repeated scans could not represent one authoritative snapshot.

Fix: capture under the shared room mutation owner through bounded indexed locker pages. Current locker V2 indexes use sortable 8-byte keyspace encoding; version 3→4 rebuilds keys while retaining exact original payload bytes. Frozen historical declarations/codecs remain unchanged. Snapshot pages are durable immutable response bytes with one fixed room watermark, cryptographic random tokens, a 60-second default lease, operation/room/session/keyspace/page-size binding, and finite global/per-room/retained-byte admission. Continuations work across replicas/database reopening. Invalid or expired tokens reject explicitly. Expired leases and all their pages are pruned in bounded batches; session revocation can remove owned pages through deleteAllForSession.

Each page has at most 64 records and fits the 8 MiB envelope; complete legacy responses exceeding count/bytes reject RESOURCE_EXHAUSTED rather than silently truncating. Capture itself has finite record/byte limits. Small/empty responses allocate no lease. SubscribeAndSnapshot installs its subscription in the same transaction as capture and page persistence. Capability is advertised only by stores supporting the bounded durable contract.

Validation: SnapshotPagingTest covers public130-row paging across replacement/new insertion, immutable watermark, exact record completion, actual SQLite reopen, foreign operation/room/session/keyspace/page-size rejection, expiry, lease exhaustion, legacy count exhaustion and session lease cleanup. Historical StorageAdoptionTest preserves all captured payload/unknown bytes across key rebuild and reopen; inbox paging and invalid stored-envelope repair remain green. Baseline red and final green logs are included.
