# F43 — signed subscription intent order

An actual HTTP regression pauses an authenticated subscribe before server proof consumption. The SDK cancels that RPC and successfully unsubscribes the same SID/room; its durable local intent is removed and the server row is absent. Releasing the original handler then commits the older subscribe, restoring the row. The test fails with `late old subscribe restored the revoked subscription` against checkpoint845fbfd plus the bounded-retirement fix73656c8. Evidence: `evidence/runtime-subscription-http-order.log` and `evidence/F43-subscription-order-red.xml`. The server handler and client are lifecycle-owned and fully drained by the fixture.

Local job cancellation and stale-response guards cannot establish remote intent order. Remediation remains open: additive signed intent revisions for both ordinary subscriptions and snapshot hydration, durable SDK revision allocation before RPC, and atomic server per-SID/room revision comparison retaining unsubscribe tombstones while that SID remains authoritative. Older/conflicting intents must not mutate subscription state. Snapshot continuation must bind the same revision. Preserve frozen schemas and legacy wire behavior through additive definitions, explicit migration and negotiated capability; custom storage extensions must explicitly opt into the required durable operation contract.

Final verification must include the actual HTTP late-commit test, same-session client restart, both intent directions, snapshot continuation versus unsubscribe, two-handle PostgreSQL CAS, historical storage reopen, legacy/new wire compatibility, and all affected platform/consumer checks. No final approval is claimed here.
