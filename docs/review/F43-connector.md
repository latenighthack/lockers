# F43 — Durable, ordered subscription intents

A held old subscribe can reach the same live session after a newer unsubscribe has succeeded. Ignoring its obsolete reply does not prevent the old server-side effect. The server's actual HTTP red reproduction is paired with SDK baseline failures showing revision0 on every operation and inability to repair a current server floor (`/tmp/connector-subscription-revision-red.log`).

The SDK now commits a positive monotonic room intent revision and desired subscription atomically before RPC. A new bounded ledger survives removal and same-session client replacement; history never resets merely because the desired subscription row is deleted. Its additive V7 migration preserves all frozen V3–V6 declarations. `maxSubscriptionHistories` defaults100000, must cover the active intent bound, and rejects new namespace admission atomically with a typed permanent history-capacity error. It does not silently prune revisions while an old session may still be live.

Every ordinary subscription and every hydration snapshot page binds the same immutable intent revision in its fresh session proof. Snapshot single-flight keys include revision, preventing a new intent from joining an old in-flight read. Direct refresh/hydration first obtains persisted subscribed intent. Servers must advertise subscriptionRevisions; absent/false capability fails observably with desired intent retained. Standalone unit controllers explicitly inject a supported probe; production uses real capability negotiation, with the high-level cached capability seam shared across hydration/reconciliation.

STALE_INTENT repair is reducer-owned. Only the still-current desired room/session/generation and matching durable revision can advance above the server's floor and issue a new intent. Obsolete responses never advance history or replay. Three guarded repairs are allowed; persistent conflict then reports a typed terminal error and keeps intent. Normal ambiguous retries keep the same revision and renew only proof nonce/signature. Unknown protobuf subscription metadata survives updates/confirmation. All identities are frozen before storage suspension. Subscription work state clears only after the parent job actually finishes joining its children; stop marks retained effects retiring and clears queued projections.

Seven revision regressions cover same-SID replacement after unsubscribe, safe floor1→6 repair, obsolete floor100 rejection, bounded conflict retries, unsupported capability, history admission rollback, and actual SQLite V6→V7 migration/removal/reopen with unchanged unknown metadata. Together with prior actor/budget and archive safety tests they pass in `/tmp/connector-subscription-revision-final-unit.log` using the immutable indexeddb-final dependency manifest. Complete integrated server/SDK/platform verification follows after the paired server CAS commit is integrated. No generated binding was edited.

Confirmation now performs an atomic durable compare-and-set on room/revision/desired kind before updating or deleting the membership row. A stale successful reply from a second controller sharing the same store and SID cannot restore a revoked subscription or delete a newer resubscription. Both directions are reproduced through signed real HTTP, with the old reply gated after server commit; the original implementation fails both tests (`/tmp/connector-subscription-confirmation-cas-red.log`).

Startup treats its row list as identity discovery only. It restores current membership and revision atomically, bootstraps only a missing legacy sidecar, and never creates a new intent from an obsolete snapshot. A gated startup snapshot reproduces the previous unsubscribe2→subscribe3 resurrection (`/tmp/connector-subscription-startup-cas-red.log`). Successful ordinary and snapshot replies must echo the exact requested positive revision before confirmation or cache publication; zero/mismatched success replies fail permanently (`/tmp/connector-subscription-echo-red.log`). Encoder validation matches the existing frozen decoder bounds without changing valid frame bytes.
