# F37 — recoverable agent outcomes

A transaction decorator cancelled a request immediately after the physical source/receipt commit. The baseline default agent receipt stayed uncertain after service restart (`AgentRecoveryTest`, `/tmp/runtime-F37-red.log`). Invalid derived IDs and Long.MAX_VALUE derived versions both produced wrong successful outcomes without their guards (`/tmp/runtime-F37-derived-red.log`). Discovery with a changing time bound failed to advance beyond64 blocked prefixes (`/tmp/runtime-F37-pagination-red.log`). A telemetry teardown mutating an extension's retained output changed the committed locker before output freezing (`/tmp/runtime-F37-freeze-red.log`). These reproductions pass after remediation.

Source writes persist immutable input, exact source locker IDs/versions, write identity, installed agent version and effect identity atomically in an additive journal. The known zero-effect default completes inside that source transaction. Explicitly installed extensions retain their existing privileged server authority. Custom extensions execute in four owned recovery workers after `RoomServiceImpl.start()`, with30s cooperative execution deadlines and bounded retries. A caller waits at most5s for an outcome; disconnecting cancels only its observation. Construction alone never starts those workers, and joined service cleanup cancels them.

`IdempotentLockerAgentRegistry` explicitly promises repeatable effects and derived output for an immutable effect identity/version. Only that contract permits re-execution after interrupted Running work. A returned result is durably saved before derived application, so Ready work recovers without another external call. Arbitrary interrupted or throwing effects become Indeterminate, and block later agent work for the same room. Installed-version changes also become Indeterminate. The trusted `reconcileWriteOutcome` seam compares the retained effect identity and either declares failure or applies independently known derived output; it never re-invokes the effect. No public unauthenticated reconciliation RPC exists.

A captured room mutation fence, same-room source/derived transactions and journal UUID lease CAS protect application and completion. Expired/stale leases cannot install results. Derived output is frozen before telemetry teardown or database waits, validated for identifier/envelope/count/complete-event byte limits, and rejects version exhaustion before any derived commit. Manual reconciliation also freezes its input and checks output bounds. Pending, Running and Indeterminate records never age-prune. Applied/Failed journal records and matching source receipts retain31days; bounded indexed pruning removes them together. Retained admission includes historical receipts and finite global/per-room limits. Historical receipts missing executable inputs are adopted in bounded pages as Indeterminate, never blindly replayed.

GetWriteOutcome returns metadata only, prefers exact retained source identities and uses bounded canonical public-read admission. The public cold server extension Flow observes precise states; the connector separately provides a finite-deadline client Flow and immutable committed-source exception metadata. Existing room reads retain their explicit public read contract.

Validation:24focused tests, zero failures/skips, including actual PostgreSQL restart through a new database handle, competing handles for retained capacity and stale-result fencing; expired idempotent/non-idempotent leases; Ready recovery; source caller cancellation; ownership loss during effect execution; pagination starvation; output mutation; IDs/count/complete-event bounds/MAX rollback; retention and historical metadata. Runnable host compilation passes. Manifest `dependencies-final-upstream.json`, final log `/tmp/runtime-F37-final.log`. This implementation does not claim exactly-once external effects for arbitrary extensions: their uncertainty is durable and requires trusted reconciliation.
