# F26 — Owned coroutine lifetimes and complete drain

Two failing reproductions showed component shutdown closing a provider and returning before active send cleanup, and extension startup failure leaving an earlier extension running.

Fix: ServerCore exposes a configurable parent CoroutineContext and supplies a supervised child lifetime to all services. Delivery workers start explicitly during component start. Session watch is a cold channelFlow with per-collection state and a producer owned by the session service; caller cancellation and service cancellation both terminate it. Push shutdown cancels/joins its fixed pools, releases unconsumed leased handoffs, then closes every provider. Shard dispatcher drain waits for whole suspended operations. Room/session/worker/component expose suspend closeAndJoin (push stopAndJoin); compatibility blocking adapters reject invocation from owned service work to prevent self-deadlock. Repeated start and start after close are rejected.

Component drain closes extension work and services before releasing ownership and coordination. New extensions receive an owned scope, retaining legacy start/stop boundaries. Startup failures unwind extensions/services; factory failures unwind earlier factory results. Runnable parent contexts, startup rollback, listener-first shutdown, joined cluster polling, and owned database/metrics cleanup complete the production lifecycle.

Validation: 39 discovered focused server tests and :server:run:compileKotlin passed. Tests cover both original lifecycle failures, embedding parent cancellation reaching an active provider, suspended shard close waiting plus self-close rejection, factory failure rollback, streams/heartbeat, cancellation, queue/revision behavior, claim drain, and owner recovery. Generated DI was inspected read-only to verify each service receives ServerCore.coroutineContext. Root owns test/route convenience attachment application lifecycle integration.

Phase 2 follow-up: a custom single-thread embedder reproduced the absence of a safe blocking-adapter restriction. Adapters now reject custom supplied dispatchers and require suspend shutdown; the strengthened test runs extension cleanup on that same dispatcher and proves suspend drain completes promptly. Provider closeAndJoin awaits asynchronous vendor teardown: APNs only closes initialized lazy clients and awaits close futures, and FCM owns an independently named application, rolls it back on initialization failure, and deletes it on close. Partial provider construction closes earlier results and suppresses cleanup failures on the original error. 34 targeted tests plus runnable compilation passed, including asynchronous provider close and construction failure rollback.
