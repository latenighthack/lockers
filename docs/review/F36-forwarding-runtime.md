# F04 / F36 — recover public writes through the public seed

Production claim addresses advertise the authenticated private listener. Previously, a failed east-west forward fell through to `NOT_OWNER` with that address. A peer handoff response was also relayed unchanged. The SDK decode layer could therefore cache a private endpoint and encounter HTTP 401 on its next attempt. An unauthenticated `fwd=1` query also suppressed forwarding and exposed the private redirect.

Reproduction: `PublicForwardingRecoveryTest` starts actual CIO public and private HTTP listeners, checks the private credential before dispatch, and uses the real SDK `RoutingRpcClient`. All four initial regressions failed against the unchanged server: transient peer failure, ownership handoff, forged marker, and ownership fence loss (`/tmp/runtime-forward-red.log`).

Fix: when a peer token is configured, public failed forwards and peer `NOT_OWNER` responses become RPC `UNAVAILABLE` without a private redirect. The seed invalidates its ownership cache and stale forward stub. A subsequent attempt resolves placement again through the public seed. Only an exact, constant-time-checked peer credential can authorize the one-hop forwarding marker. Authenticated stamped peer calls still return their handoff redirect and never forward again. Explicit legacy configurations without a peer token preserve direct-address redirects and stamped-call behavior. The commit-fence loss path follows the same public boundary. A caller deadline remains cancellation; it is not converted to an owner failure.

The final six HTTP regressions cover early peer failure, a reply lost after source commit followed by exact receipt replay (source version remains 1), handoff recovery, every write response (single/batch/delete/lock/unlock), missing/wrong forged credentials, peer one-hop behavior, legacy compatibility, caller cancellation, and loss of ownership after source mutation. The last case verifies the source body and durable write receipt both roll back.

Validation: `:server:test --tests '*PublicForwardingRecoveryTest' --tests '*GatewayBoundaryTest' --tests '*ClaimRoomOwnershipTest' --tests '*WholeRoomOwnershipTest' :server:run:compileKotlin`, using the immutable `dependencies-final-upstream.json` Fullhouse manifest and its isolated Maven repository. Final selection: 21 tests, zero failures or skips; runnable host compilation passes (`/tmp/runtime-forward-final-green.log`). The server adds a test-only connector dependency to exercise the real route cache.

A wider intermediate 28-test run also exposed two historical fixture failures: an empty locker envelope in `RoomOwnershipTest`, and a session cancellation mock returning `SESSION_EXISTS` before its throwing create path. These were reported to the integrating agent; they are not failures of the forwarding path and are handled by the repository-wide fixture update.

Follow-up: the catch-all forwarding failure handler also turned permanent peer operation errors into retryable `UNAVAILABLE`. Two additional actual HTTP regressions reproduced that misclassification and exhausted the default retry budget. Forwarding now preserves every operation RPC code and its existing `Codes.retriable()` policy, rebuilding exceptions with a public path and a safe diagnostic. Transient operation failures still invalidate placement and stale transport state. In configured private-peer mode, `UNAUTHENTICATED` / `PERMISSION_DENIED` describe the peer transport credential boundary and recover through the public seed; legacy direct-address operation authorization errors remain terminal.

The real HTTP chain also exposed upstream status erasure from ambiguous HTTP statuses. Paired ktbuf commit `ac9b89c` (publisher `780bcc0`) adds exact validated numeric status metadata across the server and all platform clients, keeping the original no-header fallback. The immutable `dependencies-status-final.json` manifest pins that publication. Final runtime selection is now 24 tests (nine forwarding HTTP tests), zero failures or skips, plus runnable host compilation. Every failure code survives the public/private chain; the SDK's default backoff makes exactly one attempt for permanent operation failures. Logs: `/tmp/runtime-forward-status-red.log`, `/tmp/runtime-forward-status-final.log`; paired evidence is `ktbuf/docs/review/F36-http-status.md`.
