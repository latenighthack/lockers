# F33 — bounded connector retention and work discovery

Reproduction: 1,000 completed distinct mutations left 1,000 lock entries (`/tmp/connector-F33-repro.log`). The existing ACK implementation loaded all confirmed history before filtering. Added recovery stores also required an explicit upgrade for previously configured databases.

Fix:
- Mutation identities reference-count active/queued users and evict in non-cancellable cleanup. Reads, mutations and watcher identities cap admission at 1,024; the network queue caps at 256. The subscription reducer uses a 64-command channel, closes it on shutdown, and uses disposable conflated wakeup hints while its persisted intent/state remains authoritative.
- ACK V2 preserves frozen protobuf payload/index bytes and adds an indexed pending flag. Stream replay queries/sends pages of 64. Confirmation age is stored separately; explicit pruning must use a cutoff older than the server's maximum replay horizon. Unknown legacy ages conservatively begin at first maintenance. Pending ACKs are never pruned; unknown fields survive confirmation.
- Application event retention requires the minimum persisted cursor across every independent consumer. Explicit pruning deletes 64 rows per transaction and advances a durable floor; stale cursors throw `ConnectorCursorExpiredException`. Default admission limits are 100,000 journal records, 64 MiB journal payload/identity bytes, 100,000 ACKs and 100,000 cached locker identities. Applications configure their limits through the factory. Exhaustion rolls acceptance back before ACK; a committed source write reports a typed committed/local-capacity exception. Atomic batch cache acceptance also rolls back together.
- Private pending ratchets cap admission at 1,024; latest-per-authority-scope archives cap identities at 10,000 and remove only authoritatively obsolete epochs. Private keys require trusted confidential storage, encrypted/secure delegates and controlled backups; ordinary locker/cache/watch/broadcast APIs do not expose them.
- `ConnectorStorage` retains the historical configured V3 definitions and upgrades explicitly to V4, preserving historical payload bytes and creating additive stores. Tombstone high-water records remain until a protocol-safe horizon is defined; cache admission bounds their growth without unsafe resurrection.

Verification: five retention tests pass for map eviction, cancelled waiter serialization, explicit event quota/prune/stale cursor handling, indexed ACK pages and horizon pruning, and a real SQLite configured V3→V4 upgrade preserving unknown bytes. Frozen legacy adoption and connector/ratchet regressions also pass (`/tmp/connector-F33-fix.log`). Uses immutable indexed ktstore pin `0.2.0-fh.8537944059d143be8704`; server outbox/receipt/session retention is owned by the server workers.
